## 2. 섹터 9 구현

### 2-1. `/agent/resume` 수신 - Tomcat FilterChain 선점

문제: 최초 `DispatcherServlet.doDispatch()` hook으로 resume을 처리하려 했으나 Spring Security가 `/agent/resume`을 먼저 처리해 `302 /auth/login redirect`를 반환했다.

확정 방향: Tomcat `ApplicationFilterChain.doFilter()` hook으로 앞당겨 처리한다. Spring Security 통과 전 agent가 내부 endpoint를 선점한다.

신규 파일 6개:

- `instrument/TomcatFilterChainClassVisitor.java`
- `instrument/TomcatFilterChainDoFilterAdapter.java`
- `instrument/TomcatFilterChainInterceptTransformer.java`
- `trace/AgentHttpBridge.java` - `install()` / `safeIntercept()` / `safeEnterOrHandle()` facade
- `trace/AgentInternalRouter.java` - `/agent/resume` URI 판별 + `ResumeHandler` 위임, `/api/agent/resume` hijack 방지
- `trace/ResumeHandler.java` - `RESUME_LOGGING` 명령 검증, `commitHash` 검증, `markLogOn()` + `notifier.start()`

### 2-2. LOG_OFF 전환 (`LogReadyNotifier`)

수정 내용:

- 생성자에 `AgentStateHolder stateHolder` 추가
- `onClosed()`: `isLogOn()` false면 큐잉 건너뜀
- `sendWithRetry()`: `boolean` 반환으로 변경. 최종 실패 시 `stateHolder.markLogOff()` + `queue.clear()` + `return false` -> worker 종료
- `start()`: 조건을 `worker != null && worker.isAlive()`로 변경해 resume 후 재시작 가능하게 함
- `runLoop()`: `finally`에서 `clearWorkerIfCurrent()` 처리

### 2-3. `DispatcherServletDoDispatchAdapter` 수정

- `safeEnter(request)` -> `safeEnterOrHandle(request, response)` 변경
- 반환값 `true`이면 즉시 `RETURN` (internal 요청 처리 완료, 일반 dispatch 진행 안 함)

### 2-4. `AgentPremain` 수정

- `RuntimeMethodBridge.installStateHolder(stateHolder)` 추가 (LOG_OFF 시 trace 차단 연결)
- `LogReadyNotifier` 생성자에 `stateHolder` 전달
- `AgentHttpBridge.install(stateHolder, commitHash, notifier)` 추가
- `TomcatFilterChainInterceptTransformer` addTransformer 추가
