- FILE: ERROR만 날짜 롤링 (`SizeAndTimeBasedRollingPolicy`)

### 핑퐁 과정 요약

**딴지 2 — `org.springframework: WARN`이 배치 로그 차단 (Claude)**
`org.springframework.batch: INFO` 별도 추가로 해결.

**파일 수정 관련 사고**
Claude가 명시적 지시 없이 `logback-spring.xml` 등 3개 파일을 직접 수정하는 실수 발생. 원복 후 규칙 재확인. CLAUDE.md 외 파일은 명시적 "수정해/반영해" 지시 전까지 절대 수정 금지.

## 3. agent 7-1 (HTTP context + endpoint 귀속)

### 범위
- `DispatcherServletDoDispatchAdapter` — ASM으로 `DispatcherServlet.doDispatch()` hook
- `HttpRequestContextBridge` — ThreadLocal 적재/해제 (fail-open)
- `HttpRequestContextHolder` — ThreadLocal 보관
- `HttpRequestContext` — method + requestUri VO
- `EndpointRegistry` — `AtomicReference<Map>` 원자적 교체
- `EndpointResolver` — 후보 0/1/2+ 분기, URI 매칭
- `ResolvedEndpoint` — 귀속 결과 VO

### 주요 설계 결정

**DispatcherServletDoDispatchAdapter — try/finally 삽입**
```
visitCode: visitTryCatchBlock(start, end, handler, null) → safeEnter(arg0)
onMethodExit(opcode != ATHROW): safeExit()
visitMaxs: endLabel → handlerLabel → safeExit → rethrow
```
Label 3개 필드로 선언 (`startLabel`, `endLabel`, `handlerLabel`). `throwableLocalIndex` newLocal로 할당.

**safeEnter/safeExit — fail-open**
- reflection 실패 시 `clear()` 후 `AgentLog.warn()` 삼킴
- `isFatal()` VirtualMachineError/ThreadDeath만 재전파 (`throw (Error) t`)
- `throw t` 컴파일 오류 → `throw (Error) t`로 수정 (딴지 수용)

**EndpointRegistry — HashMap**
- `AtomicReference<Map<Integer, List<EndpointInfo>>>` 원자적 교체
- `HashMap` 사용 (키 조회용, 순서 불필요 — LinkedHashMap 사용 금지)
- 불변 조건: endpointId 양수, entryType/entryKey non-blank, endpointId 중복 금지

**EndpointResolver — URI 매칭**
- 후보 0 → `NO_CANDIDATE`
- 후보 1 → 바로 채택
- 후보 2+ + http context 없음 → `HTTP_CONTEXT_MISSING`
- 후보 2+ + http context 있음 → HTTP method + URI 매칭
  - 매칭 0 → `NO_HTTP_MATCH`
  - 매칭 1 → 채택
  - 매칭 2+ → `AMBIGUOUS`
- URI 매칭: segment 단위, `{...}` single-segment wildcard 지원, `*/**` 미지원

**javax/jakarta 이중 지원**
`DispatcherServletClassVisitor`에서 두 descriptor 모두 체크, 매칭된 것만 instrument.

## 4. agent 7-2 (trace 직렬화 + 파일 기록 + 롤링)

### 범위
- `TraceLogSerializer` — `RuntimeTraceContext` → 1줄 JSON (JDK-only, 수동 조립)
- `TraceLogWriter` — 파일 기록 + slot 기반 롤링
- `RuntimeMethodBridge.exit()` 수정 — root exit 시 flush
- `AgentPremain.java` 수정 — `TraceLogWriter.install()` 추가

### 주요 설계 결정

**JSON 키 확정**

| JSON 키 | getter |
|---------|--------|
| `traceId` | `getTraceId()` |
| `entryMethodId` | `getEntryMethodId()` |
| `entryFqcnMethod` | `getEntryFqcnMethod()` |
| `endpointId` | `getEndpointId()` |
| `endpointEntryType` | `getEndpointEntryType()` |
| `endpointEntryKey` | `getEndpointEntryKey()` |
| `endpointHttpMethod` | `getEndpointHttpMethod()` |
| `requestMethod` | `getRequestMethod()` |
| `requestUri` | `getRequestUri()` |
| `endpointResolutionStatus` | `getEndpointResolutionStatus()` |
| `timestampMs` | (호출 시 주입) |

null 값은 JSON `null` 출력, 필드 생략 없음.

**root flush — try/catch/finally 보장**

```java
if (context.isEmpty()) {
    try {
        long now = System.currentTimeMillis();
        String line = TraceLogSerializer.serialize(context, now);
        TraceLogWriter.write(line);
    } catch (Throwable t) {
        AgentLog.warn("trace flush failed methodId=" + context.getEntryMethodId()
                + " cause=" + t.getClass().getSimpleName());
    } finally {
        TraceContextHolder.clear();  // 반드시 finally
    }
}
```

`serialize()` 예외 시에도 `TraceContextHolder.clear()` 보장 — stale trace 누수 방지.

**TraceLogWriter — slot 기반 롤링**
- 파일명: `{loggingDir}/trace-{yyyyMMddHHmm}.log`
- slot: `System.currentTimeMillis() / (rollingIntervalMinutes * 60_000L)`
- `write()` 진입마다 slot 비교 → 바뀌면 close → 새 파일 open
- `synchronized (LOCK)` 전체 보호
- `install()` 미호출 시 `write()` no-op
- mkdirs 실패 → warn 후 skip (fail-open)
- 예외 → `AgentLog.warn()` 삼킴, 애플리케이션에 전파 없음

**TraceLogWriter.install() 위치**
`AgentPremain.java` 성공 경로 — `RuntimeMethodBridge.installEndpointResolver()` 바로 다음 줄.
(AgentBootstrapService 내부 아님 — 구조 원칙: config 수신자는 premain이 담당)

### 핑퐁 딴지 요약

| 딴지 | 내용 | 판정 |
|------|------|------|
| `clear()` finally 미보장 | `serialize()` 예외 시 stale trace 누수 가능 | 수용 |
| `install()` 위치 오류 | AgentBootstrapService가 아니라 AgentPremain 성공 경로에 위치해야 함 | 수용 |
| JSON 키 불일치 | 예시 `entryKey` → 실제 getter 기준 `endpointEntryKey`로 고정 | 수용 |
| flush 로그 개선 의견 | `trace flush failed`에 `methodId=` 포함 → 디버깅 용이 | 수용 |
